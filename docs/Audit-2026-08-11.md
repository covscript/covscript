# CovScript 代码审阅报告（第二轮：鲁棒性与实现质量）

日期：2026-08-11
分支：`fix_import`（HEAD `bb8961c`）
范围：核心对象模型与内存 / 运行时执行 / 类型系统 / 编译器管线 / 解释器·调试器·CLI·系统层

## 0. 概要

对 CovScript 源码进行第二轮整体审阅（第一轮见 `docs/Audit-2026-08.md`）。通读全部 `include/` 与 `sources/`（约 63 万字节），4 路并行深审 + 关键结论逐条人工抽查核实；已与前次审计文档交叉去重，仅保留**新增**或**仍开放**的项。

共记录 **6 项严重、15 项中等、约 20 项轻微**。最突出的新风险集中在：

1. **脚本可触发的崩溃/OOM**：数组负下标无限增长、整数除零 SIGFPE、`extension` 空函数指针调用、REPL `loop_depth` 编译期检测遗漏。
2. **架构级正确性**：fiber 与主线程共享进程全局值栈，跨协程函数调用互相踩踏。
3. **复制粘贴类缺陷**：`hash_set.clear` 被注册成 `empty`、CLI 参数校验条件重复项、`range_iterator::operator!=` 用 `<` 实现。

## 1. 严重问题（脚本可触发崩溃 / OOM / 功能错误）

### C1 [严重] 数组负下标越界导致数组无界增长 → OOM / 挂死【新增】
`include/covscript/impl/type_ext.hpp:1296-1304`（`index_ref<cs::array>`）
```cpp
if (idx < 0)
    idx = arr.size() + idx;   // size_t 与 long long 混算
while (idx >= arr.size())     // idx 为负转无符号恒为巨数 → 恒真
    arr.emplace_back(var::make<numeric>(0));
return arr[idx];
```
- `arr.size() + idx` 为无符号运算，负数回绕后赋回 signed；`idx >= arr.size()` 比较时 `idx` 再转无符号成巨数 → 恒真 → 无限 `emplace_back` 直至 OOM/挂死。
- 触发：`var a=[1,2,3]; a[-4]=1;`（或任意 `-(size+1)` 及更小的下标做左值赋值）。
- 左值读路径 `return arr[idx]`（`size_t` 索引）同为越界 UB。
- **建议**：`idx < 0` 时若 `-idx > size()` 直接抛 `lang_error`（越界），不要用无符号混算补偿。

决定：负下标仍应保持自动增长语义。修复计算逻辑即可

### C2 [严重] 整数除零 / 取模零 → SIGFPE / 整型除零异常，进程崩溃【新增】
`include/covscript/core/components.hpp:479`（`std::lldiv`）、`:491`（`data._int / rhs`）、`:507`（`data._int % rhs.data._int`）
- 调用链 `parse_div`(runtime.cpp:72) → `any::operator/` → `numeric::operator/` 全链路无零值检查。`std::lldiv`/`%` 除数为 0 是 UB，实际 SIGFPE（Linux）或整型除零异常（Windows）直接杀死进程。
- 触发：脚本 `1 / 0`、`1 % 0`。浮点分支（0b00/0b01/0b10）得 inf/NaN 不崩，仅 int/int 崩。
- 注：前次审计 F8 仅记 `int_pow` 溢出，未覆盖除零。
- **建议**：`int/int` 分支先判 `rhs==0` 抛 `runtime_error`。

决定：可判定，应抛lang_error，允许用户捕获

### C3 [严重] `hash_set` 的 `clear` 被注册成 `empty`（复制粘贴错误）【新增】
`sources/instance/type_ext.cpp:652`：`.add_var("clear", make_cni(empty, true))`
- 应为 `make_cni(clear, true)`；对比 `hash_map` 的 `clear`（type_ext.cpp:728）是正确的。
- 触发：任何脚本对 `hash_set` 调用 `clear()` 后集合仍保留全部元素。
- 纯功能性 bug，一行修复。

### C4 [严重] `extension` 构造：缺 ABI 符号时对空函数指针 `dll_check()` → 崩溃【新增】
`include/covscript/core/core.hpp:1354-1357`
```cpp
if (dll_check == nullptr || truncate(dll_check(), 4) != truncate(COVSCRIPT_ABI_VERSION, 4))
    throw runtime_error("Incompatible Extension. (Target ABI: " + std::to_string(dll_check()) + ...);
```
- `dll_check == nullptr` 短路进入 throw 分支，但错误信息里**又调用 `dll_check()`**（空函数指针）→ 崩溃（UB）。
- 触发：加载任何缺 `__CS_ABI_COMPATIBLE__` 符号的坏/伪造 `.cse`。
- 附带：ABI 不匹配或 `dll_main == nullptr` 时抛异常不 `dll::close(mHandle)`，且 `~extension()` 为默认，每次加载失败泄漏 DLL 句柄（前次审计 G10 已记句柄常驻；空指针调用为新增）。

### C5 [严重] REPL 中 `loop_depth` 未递增 → 交互式 `break/continue` 编译失败【新增·C1 修复的遗漏】
- 主编译路径 `compiler.cpp:1507-1512` 对循环块 `++context->compiler->loop_depth`；REPL 的块分支 `sources/instance/instance.cpp:414-420` **没有**递增。
- 触发：REPL 中依次输入 `while true`、`break`、`end`。`translate_end`（codegen.cpp:507 等）重翻译 body 时 `loop_depth==0` → 抛 "Invalid 'break' statement: not inside any loop"。`reset_status`（impl.hpp:157）还会把 `loop_depth` 归零，故该问题始终存在。
- 这是上一轮 C1（break/continue 编译期检测）在 REPL 路径上的回归遗漏。

### C6 [严重] 跨 fiber 共享进程全局值栈 → 返回值写错槽位 / 栈错乱【新增·架构级】
- 返回值槽：`sources/instance/statement.cpp:859-867`（`statement_return::run_impl` 写 `current_process->stack.top()`）、`include/covscript/impl/impl.hpp:205-214`（`scope_guard::return_fcall`）与 `217-251`（`fcall_guard` 压/弹进程全局 `current_process->stack`，core.hpp:132）。
- 协程切换：`instance_type::swap_context`（impl.hpp:103-115）只换**域栈** `fiber_stack`，**从不换值栈**。
- 场景：脚本函数 `f()` 在 fiber 内执行到一半 `fiber.sleep_for`/`yield` 挂起（`fcall_guard` 帧留在全局栈）；主线程从 `fiber.resume` 返回后继续调用另一脚本函数 `g()`（再压一帧）；再 resume 该 fiber 时，`f()` 的 `return` 把返回值写进 `g()` 的槽位，fiber 的 `fcall_guard` 析构又 pop 掉 `g()` 的帧 → 相互踩踏。两个 fiber 交替（各自函数挂起）同样复现。
- **建议**：把返回值栈纳入按 fiber 切换（每个 fiber 持有自己的值栈引用，与 `cs_stack` 一样绑定/解绑），或 resume 时校验/隔离。

评论：process_context 里的 stack 不是指针之类容易换的，要不考虑每个 fiber 持有一个新的 process_context（有专门的 fork 方法），然后把 fiber_stack 和 fiber 相关的 API 移出去？确实是一个大的修改，需要多讨论

## 2. 中等问题（UB / 资源耗尽 / 错误语义）

### M1 [中] `opt_expr` 对非 signal 节点强制 `static_cast<token_signal*>`【新增·UB】
`sources/compiler/compiler.cpp:1166`
```cpp
switch (static_cast<token_signal *>(it.data())->get_signal()) {
```
- 外层 `switch(token->get_type())`（compiler.cpp:876）的 `default: break`（:877）对 `token_value`/`token_arglist`/`token_vargs` 等类型落入后，直接走到该处，把 `var`/arglist 对象内存当 `signal_types` 枚举读。
- 触发：**每一次**含字面量或函数调用的表达式优化（`f(a,b)` 的右子为 arglist）都会触发。当前"碰巧"读前几个字节表现良性，但属严格 UB（别名违规），改变 `var` 布局或开 LTO 后可能出错。
- **建议**：该处先判 `it.data()->get_type() == token_types::signal`。

### M2 [中] 同一块内多条 `import`/`using` 互相覆盖 `mResult`【新增·C5 修复的残余】
- `method_import::preprocess`（codegen.cpp:42-68）、`method_import_as`、`method_involve` 每次 `mResult.clear()` 后 push 一条；`method_import` 等是共享单例（translator `add_method` 存裸指针，compiler.hpp:75-79）。
- 块内两条 import：raw 遍 preprocess 全部执行，第二条把第一条结果冲掉；重翻译时第一条 pop 到第二条的 statement，第二条报 "missing preprocessing result"。
- 触发：
  ```
  block
  import a
  import b
  end
  ```
- 前次 C5 只解决跨编译残留，**同块多语句场景仍坏**。

### M3 [中] `int_pow`：有符号溢出 + 负大指数死循环【新增细节】
`include/covscript/core/components.hpp:337-365`
- `result *= base; base *= base;` 无溢出检查（`2^63` 溢出 UB）。
- 负指数 `2^(-1000000000)` 循环 ~10^9 次挂死；`exp == LLONG_MIN` 分支（:351-352）内部同样溢出。
- 触发：脚本 `2 ^ 63`、`2 ^ -1000000000`（`numeric::operator^` 0b11 分支）。`operator^` 声明为 `noexcept`，脚本层无法捕获。
- 注：前次审计 F8 已记溢出，负指数无界循环为新细节。

### M4 [中] `range_iterator::operator!=` 用 `<` 实现 → 负步长 range 一次都不迭代【新增】
`include/covscript/core/core.hpp:979-981`
```cpp
bool operator!=(const range_iterator &it) const { return m_index < it.m_index; }
```
- `operator==` 用 `==`、`operator!=` 却用 `<`，不对称。`range(5,0,-1)` 的 `begin=5, end=0`，`5<0` 恒假 → 循环体从不执行。
- 触发：`foreach (i in range(5,0,-1)) ...`（range 三参形式，covscript.cpp:342-353 接受任意步长）。
- **建议**：`operator!=` 改为 `m_index != it.m_index`。

### M5 [中] `numeric` 哈希不一致 + 整/浮 `==` 为真 → hash_map 键查找失败【新增】
`include/covscript/impl/type_ext.hpp:652-659`
- `hash(1)` 走 `std::hash<long long>`、`hash(1.0)` 走 `std::hash<long double>`，值不同；而 `numeric::operator==`（components.hpp:665-678）判定 `1 == 1.0` 为真。哈希容器要求相等键哈希相等 → 查找失败。
- 触发：`var m={}; m[1]="x"; m[1.0]` 取不到值 / 插入重复键。

### M6 [中] `csym` 行号重定位 off-by-one + `mLine==0` 越界【新增】
`sources/covscript.cpp:126-128`
```cpp
if (mLine >= csym.map.size()) throw ...;
std::size_t relocated_line = csym.map[mLine - 1];
```
- `>=` 把最后一行（`mLine == size`）误判非法（应为 `>`）；`mLine == 0` 时 `mLine-1 == SIZE_MAX` 越界读（UB）。
- 同模式：`sources/debugger.cpp:400-403`、`:444-447`。

### M7 [中] `parse_lnkasi`（link 赋值 `:=`）绕过常量/保护检查【新增】
`sources/instance/runtime.cpp:243-247`
```cpp
var runtime_type::parse_lnkasi(var &a, const var &b) { a = b; return a; }
```
- `a = b` 走 `any::operator=`（variable.hpp:1150-1157），无任何 `protect_level` 校验；`parse_asi`（runtime.cpp:237-241）走 `swap(raw=true)` 是有校验的。
- 触发：`constant x = 5; x := 10;` 会把槽位 var 整体替换并丢失常量标志；对模块/函数等 protected 对象同样可静默改写。

### M8 [中] `chmod_r` 会 chmod 根目录及所有中间目录【新增】
`sources/system/common.cpp:232-246`
- `split` 对 `/home/u/f` 得 `["","home","u","f"]`，`path` 初始化为 `path_separator`（:236-237），循环依次 chmod `/`、`/home/`、`/home/u/`、`/home/u/f/`。
- root 下运行会改写根目录权限；非 root 下第一步 `chmod("/")` 即失败返回 false。
- 触发：脚本调用 `system.chmod_r("/home/user/foo", "777")`。

### M9 [中] debugger 残留旧式信号/EOF 处理（interpreter 已修，debugger 未同步）【新增·G1/G2/G3 未覆盖 debugger】
- `sources/debugger.cpp:45-49`：CTRL_BREAK 在控制线程直接调用 `on_process_exit_default_handler` → `std::exit`（covscript.cpp:157），与主线程竞争、跳过 RAII 清理；interpreter.cpp:41-46 已是协作式 `raise_exit()`。
- `sources/debugger.cpp:65-69`：Unix 信号处理器用 `std::cout`（非 async-signal-safe，可重入死锁）；interpreter.cpp:62-68 已改 `::write`。
- `sources/debugger.cpp:335-343`：Win32 stdin EOF 后 `std::getline` 恒失败且无 `eof()` 分支 → 无限忙循环（interpreter.cpp:346-349 有 eof 处理）。

### M10 [中] `parse_mode` 非法串静默返回 0 → 清空全部权限【新增】
`sources/system/common.cpp:152-171`
- 数字分支不校验 `8/9` 等非法八进制位；符号分支只接受恰好 9 字符；空串/其他非法串一律 `mode = 0` → `chmod(file, 0)` 移除全部权限。
- 另 `std::isdigit(perm[0])` 传负 char 属 UB（见 M12）。
- 触发：脚本传入 `""`、`"garbage"` 等模式。

### M11 [中] lambda `function` 生命周期随编译器（`function_pool` 裸指针）【前次 B1 的残留风险】
`sources/compiler/compiler.cpp:815-828`
- lambda 的 `function*` 存入 `compiler_type::function_pool`（`vector<unique_ptr>`，compiler.hpp:249-253），同时以 `function_ptr{fn}` 裸指针存进 `var`（:822/:828）。
- 编译器（随 context shared_ptr 存活）被释放而 lambda var 仍存活（全局 GC 使语句不朽）→ 调用即 UAF。
- 触发：REPL / `create_subcontext` 中在已销毁 context 的编译器里定义 lambda 并保留引用。

### M12 [中] `std::isspace/isdigit/tolower/isalnum` 等传入负 `char` → UB【新增·多处】
`instance.cpp:490/504/509`、`debugger.cpp:355/359/363/463/595/542`、`system/common.cpp:157`、`type_ext.cpp:467-530/1979-1993`
- x86/MSVC 下 `char` 有符号，UTF-8 高位字节（≥0x80）为负值，`std::is*(int)` 要求 `unsigned char` 或 EOF → 查表越界（MSVC 调试断言）。
- 触发：REPL/debugger 输入含多字节字符的命令行；对含中文的字符串调用 `to_lower()/to_upper()` 或 `char` 判断函数。
- **建议**：统一 `static_cast<unsigned char>`。

### M13 [中] `numeric::as_integer()` 浮点→整型越界窄化 UB【新增】
`include/covscript/core/components.hpp:765-771`：`long double` 越界（或 NaN）转 `long long` 是 UB。触发：`(1e300).to_integer()`、`math.constants.float_max.to_integer()`。
- 同文件 `operator+/-/*/++/--`（:396-533、:713-745）均为无保护的有符号溢出 UB。

### M14 [中] `local_time`/`utc_time` 空指针解引用【新增】
`sources/instance/type_ext.cpp:1697-1727`：`*std::localtime(&t)`/`*std::gmtime(&t)` 在 `time_t` 超范围时返回 `nullptr`，未检查即解引用崩溃。

### M15 [中] `tree_type::insert_root_left/right` 新根不更新旧根的 `root` 指针【新增·潜伏 UAF】
`include/covscript/core/components.hpp:1276-1308`、`emplace_root_*`（:1354-1388）
- `it.mData == mRoot` 分支 `new tree_node(nullptr, mRoot, ...)` 后，旧根 `root` 字段仍为旧值。
- 此后对旧根再做 `emplace_root_*`（`it.mData->root->left` 解引用空指针）或 `reserve_left/right`（compiler.cpp:983-991 常量条件折叠路径）会把子树挂到错位置并 `destroy` 还被 mRoot 引用的节点 → use-after-free。
- 触发：`a * b + c`（低优先级运算符上插）即产生陈旧根节点；嵌套三元表达式 `a ? b ? c : d : e` 常量条件折叠时最可能命中。

## 7. 落实方案（逐条，含对已加评论/决定的反馈）

### 7.0 已加评论/决定的反馈

- **C1（决定：负下标保留自动增长语义，仅修计算逻辑）**：采纳。只改 `index_ref<cs::array>` 的算术，不做"越界即抛"。见 §7.1。
- **C2（决定：抛 `lang_error`，允许脚本捕获；但符号溢出相关优先保证性能）**：采纳。`numeric::operator/`、`operator%` 均为非 `noexcept`，可安全抛异常；`statement_try`（statement.cpp:884）直接 `catch (const lang_error &)` 并写入捕获变量，脚本 `try/catch` 可捕获。后续补充决定：**int/int 除零只加一个可预测的零值分支（代价可忽略），若基准测试显示影响显著，则退化为文档化 tradeoff**。见 §7.2、§7.19。
- **C6（决定：`fiber_context` 收容 fiber 链/调度参数；每非 native fiber 一个 forked `process_context`，换入换出 `current_process`）**：采纳并定稿。`fiber_context` 只装 `stack`（fiber 链，原 `process_context::fiber_stack`）与 `busy_wait_coef/min`（类名已含 fiber 语义，成员去 `fiber_` 前缀）；**函数值栈 `process_context::stack` 及全部执行栈访问点不动**——隔离靠每个非 native fiber fork 自己的 `process_context`（值栈从空开始），`cs_swap_in/out` 切换 `current_process`。见 §7.6。
- **M13/有符号溢出（决定：优先保证性能，不加热路径检查）**：采纳。`numeric` 的 `+ - * ++ --` 与 `as_integer()` 浮点→整型窄化**不做运行时检查**，文档化为已知边界（含 MSVC 下 long double==double 的舍入行为）。见 §7.19。
- **L19 `type_id::is_a`（要求解释；决定：不处理）**：见 §7.22 的 L19 行与下方说明——经核查当前**无脚本路径能构造"无 node 的通用 structure type_id"**，该混合分支实际不可达，属防御性/潜伏问题。**按决定不做修改**，仅保留说明。

### 7.1 C1 数组负下标自动增长（只改算术）

`include/covscript/impl/type_ext.hpp:1296-1304`：
```cpp
template <>
var &operators::index_ref<cs::array>(cs::array &arr, const var &pos)
{
    cs::numeric_integer idx = pos.const_val<cs::numeric>().as_integer();
    if (idx < 0) {
        idx += static_cast<cs::numeric_integer>(arr.size());   // 负下标从尾部计数
        if (idx < 0) {                                          // 仍落在头部之前 → 前插补零
            std::size_t pad = static_cast<std::size_t>(-(idx + 1)) + 1; // idx<0，故 idx+1<=0，无溢出
            arr.insert(arr.begin(), pad, var::make<cs::numeric>(0));
            idx = 0;
        }
    }
    while (idx >= static_cast<cs::numeric_integer>(arr.size()))
        arr.emplace_back(var::make<cs::numeric>(0));
    return arr[static_cast<std::size_t>(idx)];
}
```
- 语义保持：`a[-1]`→末元素；`a[-4]`（size=3）→ 前插 1 个零、落在新 `a[0]`；`a[5]`→尾增到 size 6。全程 signed 运算，比较前显式转 signed，杜绝无符号回绕。
- 验证：`a=[1,2,3]; a[-4]=5;` 应得 `[0,5,2,3]`（前插 1、写 index 0）；`a[-1]=9` 仍改末元素；`a[10]=1` 尾增到 11 元素。读路径 `index<cs::array>`（type_ext.hpp:1306-1310）的 `.at()` 已保证越界干净报错，可顺带把 `std::out_of_range` 包装为 `lang_error`（见 M 项）。

### 7.2 C2 整数除零 / 取模零 → 抛 `lang_error`

- `operator%(const numeric&)` 0b11 分支（:507）：

- **性能决策**：`int/int` 除零分支是一个"恒不命中"的可预测比较（约 1 条指令），对热路径影响可忽略；且不检查会导致 SIGFPE 直接杀死进程。故**保留检查 + 抛 `lang_error`**。若后续基准显示该分支可测影响（理论上不会），则按决定退化为文档化 tradeoff（注释说明除零为 UB）。
- 说明：`lang_error` 不带位置时，脚本内 `try/catch` 仍可捕获（statement_try 只按类型匹配）；若未捕获，由 instance::interpret 包装为 fatal。与现有 `hash_if`/`to_integer_if` 抛 `runtime_error` 的模式不同，此处按决定走 `lang_error`。
- 验证：`try { 1/0 } catch(e) { println(e) }` 不崩溃且打印错误；`1%0` 同；对照优化与 `-o` 模式行为一致。

### 7.6 C6 fiber 值栈隔离（`fiber_context` 收容 fiber 相关成员 + 每非 native fiber 一个 `process_context`）

**现状**：`current_process` 是全局指针（core.hpp:229）。`process_context` 里有两类栈，必须区分：
- `stack`（`stack_type<var>`，core.hpp:132）= **函数值栈**（`fcall_guard`/`statement_return`/`scope_guard::return_fcall` 用的返回值槽）——**本方案不动它**。
- `fiber_stack`（`stack_type<fiber_t>`，core.hpp:132）= **fiber 链**（`fiber::current/within` 与调度用）——它和 `fiber_busy_wait_coef/min`（core.hpp:139-140）才是要收容进 `fiber_context` 的成员。

**推荐方案（按你的定稿）**
1. **新增 `fiber_context`**，只收容与 fiber 直接相关的成员：
```cpp
class fiber_context {
    stack_type<fiber_t> stack;                          // fiber 链（原 process_context::fiber_stack）
    double busy_wait_coef = COVSCRIPT_FIBER_BUSY_WAIT_COEF;
    std::size_t busy_wait_min = COVSCRIPT_FIBER_BUSY_WAIT_MIN;
};
```
   **函数值栈 `stack`、`stack_backtrace`、`eptr`、`stack_size` 全部留在 `process_context` 原样不动。**（类名已是 `fiber_context`，成员不再加 `fiber_` 前缀。）
2. **`process_context` 改为持 `fiber_context *fiber_cxt`**；`this_process` 自己持有一份 `fiber_context`（与 `this_process` 同生命周期），`this_process.fiber_cxt` 指向它。
3. **fork 语义**：`process_context::fork()`（covscript.cpp:161-174）在现有拷贝（output_precision/import_path/事件转发、值栈/回溯从空开始）之外，**直接继承 parent 的 `fiber_cxt` 指针**——即 fork 出的 process_context 与父**共享同一条 fiber 链**（fiber 链本质是协作式单线程上的进程级线性链，本就该共享）。
4. **非 native fiber**：各自持有 `std::unique_ptr<process_context> process`（`current_process->fork()`）。`current_process` 的换入换出**收进 `cs_swap_in`/`cs_swap_out`**（而非散落在 yield/sleep/entry）：
```cpp
// resume() 在切栈前捕获调用者进程，cs_swap_in 不覆盖它
fi->resumer_process = current_process;
...
void cs_swap_in()  { if (process) current_process = process.get(); ... }   // 换入 fiber 的 process
void cs_swap_out() { if (resumer_process) current_process = resumer_process; ... } // 恢复调用者
```
   yield/sleep_for/entry 只 `SwitchToFiber(prev_ctx)` 切回调用者，控制权回到 `resume()` 的 SwitchToFiber 之后，由其调用的 `cs_swap_out`（链空时恢复 `fi->resumer_process`）或 `top->cs_swap_in()`（嵌套时置为栈顶 fiber 的 process）完成 `current_process` 收尾。
   由于 fork 的值栈从空开始，**每个 fiber 在运行时 `current_process->stack` 就是自己的函数值栈**，`fcall_guard`/`statement_return` 等**现有代码零改动**，跨 fiber 踩踏即消除。
5. **改访问点**（仅被移走的成员）：
   - `current_process->fiber_stack` → `current_process->fiber_cxt->stack`：`core.hpp:360/365`（`fiber::current/within`）、`type_ext.cpp:1649-1651`、`win32/common.cpp` 与 `unix/common.cpp` 的调度（push/pop/top）。
   - `current_process->fiber_busy_wait_coef/min` → `current_process->fiber_cxt->busy_wait_coef/min`：win32/unix 调度。
   - `current_process->stack`、`stack_backtrace`、`eptr`、`stack_size`：**不动**。
6. **收尾**：`fiber::create/create_native/resume/yield/sleep_for` 公共 API 签名不变。`fiber.set_schedule_policy` 写入 `fiber_cxt`（共享链，各 process 一致）。native fiber（`create_native`）不新建 process_context，沿用当前执行路径。

**风险点（已评估）**
- `current_process` 在 fiber 切换时被改写（主线程协作式）；async 工作线程/Win32 控制线程并发读 `current_process` 属现状既有边界，需限定主线程或改 `std::atomic<process_context *>`。
- fiber 内 `system.exit`/SIGINT：fork 已把 `on_process_exit/on_process_sigint` 转发到父，方向正确。
- 非 native fiber 的 `process_context` 随 `fiber_t`（shared_ptr）销毁而回收。
- 调试器步进读 `current_process->stack.size()`：在 fiber 内读到该 fiber 的值栈——符合预期。

**改动面小结**：新增 `fiber_context`；`process_context` 删 3 个成员（`fiber_stack`/`fiber_busy_wait_coef`/`fiber_busy_wait_min`）、加 1 个指针 `fiber_cxt`；`fork()` 加 1 行继承 `fiber_cxt`；`resize_stack`（core.hpp:143-151）原 `fiber_stack.resize(child_stack_size())` 改经 `fiber_cxt->stack`（`stack`/`stack_backtrace`/`stack_size` 不动）；每非 native fiber 持 forked `process_context` 并在 `cs_swap_in/out` 切 `current_process`；仅 fiber 相关访问点（约 10 处）改经 `fiber_cxt`。函数值栈语义与全部执行栈访问点保持不变。

### 7.9 M3 `int_pow` 溢出与负大指数

`include/covscript/core/components.hpp:337-365`（`operator^` 为 noexcept，故全程不抛、溢出回退浮点）：
```cpp
static inline numeric int_pow(numeric_integer base, numeric_integer exp)
{
    if (exp == 0) return 1;
    if (base == 0) {
        if (exp < 0) { errno = EDOM; feraiseexcept(FE_DIVBYZERO); return std::numeric_limits<numeric_float>::infinity(); }
        return 0;
    }
    if (exp < 0)                            // 负指数 → 恒为浮点结果，std::pow 无循环、无溢出（消除 2^-1e9 挂死）
        return std::pow((numeric_float)base, (numeric_float)exp);
    if (base == 1) return 1;
    if (base == -1) return (exp & 1) ? -1 : 1;
    const numeric_integer base0 = base, exp0 = exp;   // 保留原值供浮点回退
    auto fallback = [&]() { return std::pow((numeric_float)base0, (numeric_float)exp0); };
    // 符号感知的有符号乘法溢出预检（负底数也正确）
    auto would_overflow = [](numeric_integer a, numeric_integer b) {
        if (a == 0 || b == 0) return false;
        if (a > 0) return b > 0 ? a > (std::numeric_limits<numeric_integer>::max)() / b
                                : b < (std::numeric_limits<numeric_integer>::min)() / a;
        else       return b > 0 ? a < (std::numeric_limits<numeric_integer>::min)() / b
                                : a < (std::numeric_limits<numeric_integer>::max)() / b;
    };
    numeric_integer result = 1;
    while (exp > 0) {
        if (exp & 1) {
            if (would_overflow(result, base)) return fallback();
            result *= base;
        }
        exp >>= 1;
        if (exp > 0) {                       // 仅在还要用时平方，消除"末次无用平方溢出"
            if (would_overflow(base, base)) return fallback();
            base *= base;
        }
    }
    return result;
}
```

### 7.10 M4 负步长 range

`include/covscript/core/core.hpp:978-981`：`operator!=` 是 range-for 的"继续迭代"条件，**必须按步长方向判断**——不能简单改成 `m_index != it.m_index`（否则正步长越过终点后 `m_index != end` 恒真 → 死循环，如 `range(0,10,3)` 走到 12 后永不等于 10）：

### 7.16 M10 `parse_mode` 非法串报错而非静默置 0

unsigned int parse_mode(const std::string &modeString)
{
    if (modeString.empty())
        throw cs::lang_error("Invalid permission mode: empty string");
    const char *perm = modeString.c_str();
    unsigned int mode = 0;
    if (std::isdigit(static_cast<unsigned char>(perm[0]))) {
        const char *p = perm;
        while (*p) {
            if (*p < '0' || *p > '7')
                throw cs::lang_error("Invalid permission mode: expected octal digits 0-7");
            mode = mode * 8 + *p++ - '0';
        }
    }
    else {

            throw cs::lang_error("Invalid permission mode: expected 3 groups of 'rwx'");
        mode = ((perm[0]=='r')*4 | (perm[1]=='w')*2 | (perm[2]=='x')) << 6

}

### 实施中发现并额外修复

1. **M15 空树崩溃**：`emplace_root_left(tree.root(), obj)` 在空树上 `it.mData==mRoot==nullptr`，原新增的 `it.mData->root=mRoot` 解引用空指针；已改为仅当 `it.mData!=nullptr` 时更新（四个 root 操作）。
2. **L2 引入的整数转浮点回归**：`parse_number` 整数路径曾误用 `static_cast<numeric_float>`，把 `1` 变成浮点导致 `1/0` 输出 `inf`；已恢复整数解析（`1e3` 走 `stold`）。
3. **debugger `collect_garbage` 置空 compiler context 崩溃**：`run` 后 `collect_garbage` 调用 `swap_context(nullptr)`，随后 `break`/`print` 的 `build_expr` 中 `this->context` 为空 → SIGSEGV；新增 `ensure_compiler_context()` 在表达式命令前重绑。
4. **`exist_record` 空栈崩溃**：debugger 在脚本结束后 build_expr，storage 的 `m_set` 为空时 `m_set.top()` 越界；已加空栈防护。
5. **quit 确认/`wait_before_exit` 忙等**：管道/重定向 stdin 下 `kbhit()` 恒假导致死等；interpreter 与 debugger 均按 `stdin_is_tty()` 跳过非交互等待。

### 遗留（未处理/按决定跳过）

- L13 `next_n/prev_n`：迭代器不持容器，无法不改变签名地做边界检查；已加注释说明限制。
- L19 `type_id::is_a`：按决定不处理。
- L21/L22：记录为已知边界，不改。
- C6 残余风险：`current_process` 跨线程访问（async 工作线程/控制线程）仍属现状既有边界；unix 侧 fiber 改动未经本机实测（逻辑与 win32 对齐）。

### C6 访问约定与兼容引用移除计划

fiber 链与调度参数的访问**一律经由 `fiber_cxt`**：

```cpp
current_process->fiber_cxt->stack;         // fiber 链
current_process->fiber_cxt->busy_wait_coef;
current_process->fiber_cxt->busy_wait_min;
```

- `process_context::fiber_stack` / `fiber_busy_wait_coef` / `fiber_busy_wait_min` 是**过渡期兼容别名**（引用到 `fiber_cxt` 对应成员），仅服务于既有外部调用方，仓库内部代码已全部改用 `fiber_cxt` 直连。
- **移除计划**：自 **3.5.3** 起移除这三个兼容成员；届时任何仍未迁移到 `fiber_cxt` 的调用方将无法编译。
- 迁移检查：`grep -n "fiber_stack\|fiber_busy_wait" --include=*.cpp --include=*.hpp` 应只命中 `fiber_cxt` 相关与兼容别名声明本身。
