# CovScript 整体审计报告

日期：2026-08-10
分支：`fix_import`
范围：编译器管线 / 运行时执行 / 核心对象模型与内存 / 纤程·平台·全局状态

## 0. 概要

对 CovScript 源码进行整体审计，发现约 55 处问题，按主题归为 9 簇。其中 1 项 critical、17 项 high。最严重的风险集中在两处：

1. **新合入的 async/fiber 特性（#126/#127）**：`is_native_callable` 的"非 function_ptr 即原生"判据过粗，把脚本 lambda 与 context 绑定 CNI 放行到工作线程/无域栈 fiber，导致解释器在非主线程执行、域栈跨 fiber 腐蚀。
2. **生命周期/GC 设计**：`function_ptr` 是语句成员裸指针，语句由全局 GC 池释放且不跑析构，嵌入式 API 与调试器在 GC 后持有悬垂函数 → UAF。

本会话已完成 6 个修复提交（见 §2），本轮计划按 Phase 1→4 修复全部问题（§5）。

## 1. 审计范围与方法

- 四个并行深审代理分别覆盖：编译器管线、运行时执行、核心对象模型与内存、纤程/平台/REPL/全局状态。
- 关键结论经人工抽查验证（async 误判、`to_string<structure>` 悬垂、break/continue 无函数边界隔离均已实证）。
- 严重度：critical > high > medium > low。

## 3. 问题清单

### A. async/fiber 线程安全（Phase 2）

- **A1 [critical]** `is_native_callable` 把脚本 lambda 误判为原生函数 → 解释器代码在 std::async 工作线程执行。`sources/instance/type_ext.cpp:1334-1337`（判据 `target_type()!=typeid(function_ptr)`）、`1356-1362`（async_callable）、`1370-1382`（await_impl → `std::async`）。lambda 编译为 `callable(cs::function)`，target 非 function_ptr → 通过检查。触发：`future.create([](x)->x+1, 1)`、`await(context.import, ...)`。修复：排除 cs::function/context 绑定 CNI/fiber 操作。
- **A2 [high]** `fiber.create(lambda)` 走 native 分支，无独立域栈，挂起时参数域泄漏/跨 fiber 腐蚀。`type_ext.cpp:1594-1601`、`statement.cpp:112-137`。触发：`fiber.create([](x)->fiber.sleep_for(x), 100)` 后主脚本引用 `x`。修复：为 cs::function target 单独识别并取 `get_context()`，创建独立域栈。
- **A3 [high]** `create_subcontext` 的 fiber_sp 引用链在二级以上导入断裂。`sources/covscript.cpp:568`（传 `cxt->instance->fiber_sp` 成员而非 `fiber_stack` 引用）、`include/covscript/impl/impl.hpp:44-46,59-69,103-115`。二级导入 C 绑到恒 nullptr 的 B.fiber_sp → fiber 内调用 C 函数域栈错位。触发：深度≥2 包链 + fiber 跨模块调用（现有 test_shared_cxt 只覆盖一级）。修复：传父 `fiber_stack` 引用。
- **A4 [high]** `fiber.resume` 是普通 CNI，可被投递到工作线程 → 跨线程 SwitchToFiber（UB）。`type_ext.cpp:1655-1658`、`sources/system/win32/common.cpp:265-352`（win32 的 global_ctx 在首个调用线程初始化）。触发：`future.create(fiber.resume, f)`。修复：检测并拒绝非解释器主线程调用。
- **A5 [high]** 销毁挂起中的 fiber 不执行其 C 栈上的 RAII：值栈槽泄漏、终结器丢失。`win32/common.cpp:223-227`（DeleteFiber）、`unix/common.cpp:291-295`（munmap）。触发：`var co=fiber.create(f); co.resume(); co=null;`。修复：禁止/断言销毁未结束 fiber，或显式 cancel。
- **A6 [high]** `future.create`/`await` 的 std::async 线程与主脚本并发操作全局 any 代理池（非线程安全分配器/引用计数）。`type_ext.cpp:1373,1407`、`include/covscript/core/variable.hpp:822-828,838-854`、`components.hpp:867-924`。修复：async 仅限纯 CNI + 文档化；或池加锁/线程局部。
- **A7 [medium]** `process_context::fork()` 监听器按值捕获裸指针 `curr`，父先析构则子 UAF；且不复制调度参数。`sources/covscript.cpp:157-170`。修复：共享所有权或文档化生命周期。

### B. 生命周期 / GC 设计（Phase 4）

- **B1 [high]** `function_ptr` 指向语句成员 `mFunc`（裸指针），语句由全局 GC 池释放 → 嵌入式 API（eval/function_invoker）、调试器函数断点、fiber_function 持有悬垂。`sources/instance/statement.cpp:828-843`、`sources/covscript.cpp:620-646`、`include/covscript/covscript.hpp:109-158`、`sources/debugger.cpp:180-260,660-717`、`type_ext.cpp:1538-1565`。修复：function 改 shared_ptr 所有权。
- **B2 [high]** `collect_garbage()`（无参）全局删除所有语句；`raii_collector` 按 context 析构 → 多 context 场景 use-after-free。`covscript.cpp:620-646`、`covscript.hpp:109-126,148-151`。触发：同进程两 context 先后销毁。修复：GC 按 context 归属；`collect_garbage(context)` 不再触发全局池回收。
- **B3 [medium]** `garbage_collector::collect()` 用 `::operator delete` 不跑析构：token_value 持有的 var 引用、tree_node 链整体泄漏。`include/covscript/core/core.hpp:1280-1285`。修复：collect 改 `delete ptr`（跑析构）或显式析构。
- **B4 [medium]** domain 反射表键为不拥有所有权的 string_view，指向 AST token 字符串；无参 `collect_garbage()` 裸删 token 后键悬垂。`core.hpp:659`、`covscript.cpp:149-155`。修复：键改 std::string，或 collect 仅限进程退出前。

## 4. 总体健康度评估

核心价值模型（引用计数 proxy + protect 级别 + scope_guard/fcall_guard RAII、domain_ref 身份比较免疫悬垂）设计健全，正常单线程路径自洽。主要风险集中在三处系统性弱点：

1. **async/fiber 的"native 判据"过粗 + 进程全局状态（值栈/GC/any 池）无线程隔离**（A 簇）——新特性引入，可由脚本直接触发。
2. **function 生命周期依赖 GC 池裸删 + 全局 GC 作用域错配**（B 簇）——嵌入式/调试器 UAF。
3. **控制流标志是无作用域全局布尔 + 优化器"折叠即执行"**（C/D 簇）——逻辑缺陷与常量不可变保证被打破。

其余为畸形输入崩溃（修复便宜）与边界健壮性问题。

## 5. 分阶段修复计划与 Phase 映射

| Phase | 内容 | 涉及条目 |
|---|---|---|
| **Phase 1 快赢** | 判空/校验、UAF、terminate、标志隔离、常量折叠写穿、win32 EOF、--no-optimize 常量 | E1-E6、F1、F2/G4、C1/C2、D1、D6、G1 |
| **Phase 2 async/fiber** | native 判据收紧、subcontext fiber_sp 链、挂起 fiber 策略、async 白名单 | A1-A7 |
| **Phase 3 状态卫生** | mResult 自包含、translate/REPL 回滚、优化器左值/副作用黑名单、constant_pool 隔离、var_id generation、平台信号 | C3-C7、D2-D5、F3-F11、G2/G3/G5-G12、H1/H2、I1-I4 |
| **Phase 4 生命周期/GC** | function 共享所有权、GC 按 context 归属、collect 跑析构 | B1-B4 |
| **Backlog** | 低优先/信息项，视需要 | J1-J4 |

## 6. 附录：关键复现用例

# D1 常量自增写穿
constant c = 5
c++

    f()
    system.out.println("never")   # 被游离的 break_block 打断

end
var s = new S
s = null      # 进程 abort

    function to_string() return "hello" end
end
system.out.println(new T)   # 读取悬垂内存

# E1 畸形输入段错误
# 单行含仅逗号的表达式 → method_expression::translate 空指针

function fib(n) if n < 2 return n end return fib(n-1)+fib(n-2) end
