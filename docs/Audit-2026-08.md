# CovScript 整体审计报告

日期：2026-08-10
分支：`fix_import`
范围：编译器管线 / 运行时执行 / 核心对象模型与内存 / 纤程·平台·全局状态

## 0. 概要

对 CovScript 源码进行整体审计，发现约 55 处问题，按主题归为 9 簇。其中 1 项 critical、15 项 high（E1/E2/E3 经二次核查降级，F3 上调；详见 §7 二次核查记录）。最严重的风险集中在两处：

1. **新合入的 async/fiber 特性（#126/#127）**：`is_native_callable` 的"非 function_ptr 即原生"判据过粗，把脚本 lambda 与 context 绑定 CNI 放行到工作线程/无域栈 fiber，导致解释器在非主线程执行、域栈跨 fiber 腐蚀。
2. **生命周期/GC 设计**：`function_ptr` 是语句成员裸指针，语句由全局 GC 池释放且不跑析构，嵌入式 API 与调试器在 GC 后持有悬垂函数 → UAF。

本会话已完成 6 个修复提交（见 §2），本轮计划按 Phase 1→4 修复全部问题（§5）。

## 1. 审计范围与方法

- 四个并行深审代理分别覆盖：编译器管线、运行时执行、核心对象模型与内存、纤程/平台/REPL/全局状态。
- 关键结论经人工抽查验证（async 误判、`to_string<structure>` 悬垂、break/continue 无函数边界隔离均已实证）。
- 严重度：critical > high > medium > low。

## 3. 问题清单

### A. async/fiber 线程安全（Phase 2）

- **A1 [critical]** `is_native_callable` 把脚本 lambda 误判为原生函数 → 解释器代码在 std::async 工作线程执行。`sources/instance/type_ext.cpp:1334-1337`（判据 `target_type()!=typeid(function_ptr)`）、`1356-1362`（async_callable）、`1370-1382`（await_impl → `std::async`）。**【二次核查·实测】** lambda **不**编译为 function_ptr：编译产物是 `callable(cs::function)`（compiler.cpp:826，`function func(...)` 局部对象），普通命名函数才是 `callable(function_ptr{&mFunc})`（statement.cpp:833-836）。实测 `future.create([](x)->x*2, 21)` 返回 42（**lambda 被 async 接受并执行**），而 `future.create(fib, 15)`（命名函数）报 "Async future can only be created from native functions"。用户疑问"lambda 不是应编译为 function_ptr 吗"——答案是否定的。**已定方案**：async（`future.create`/`await`）运行在工作线程，**必须排除全部脚本代码**——`is_native_callable` 收紧为排除 `function_ptr` **且** `cs::function` 两种 target，仅接受真正的 CNI/native callable；并文档化 async 仅限纯 CNI。**Phase 2**
- **A2 [high]** `fiber.create(lambda)` 误入 Native fiber 路径（`create_native`），无上下文/域栈，挂起时参数域泄漏/跨 fiber 腐蚀。`type_ext.cpp:1594-1601`、`statement.cpp:112-137`。**【二次核查·实测】** `fiber.create([]()->println("fiber lambda ran"))` 正常运行（native 分支，create_native），确认 lambda fiber 被当作原生处理。**【方案补充（用户）】** fiber 路径**不需要排除** function/lambda——正常 fiber 是协作式（主线程）执行，脚本代码安全；**只需防止 lambda 进入 Native fiber 路径**。修复：`fiber.create` 对 target 为 `cs::function`（lambda）的分支与 `function_ptr` 一视同仁，均走脚本 fiber 路径 `fiber::create(fptr->get_context(), fiber_function(...))`（带上下文 + 独立域栈）；仅对真正的 CNI 走 `create_native`。**Phase 2**
- **A3 [high]** `create_subcontext` 的 fiber_sp 引用链在二级以上导入断裂。`sources/covscript.cpp:568`（传 `cxt->instance->fiber_sp` 成员而非 `fiber_stack` 引用）、`include/covscript/impl/impl.hpp:44-46,59-69,103-115`。二级导入 C 绑到恒 nullptr 的 B.fiber_sp → fiber 内调用 C 函数域栈错位。触发：深度≥2 包链 + fiber 跨模块调用（现有 test_shared_cxt 只覆盖一级）。修复：传父 `fiber_stack` 引用。**Phase 2**
- **A4 [high→已决定暂缓]** `fiber.resume` 是普通 CNI，可被投递到工作线程 → 跨线程 SwitchToFiber（UB）。`type_ext.cpp:1655-1658`、`sources/system/win32/common.cpp:265-352`（win32 的 global_ctx 在首个调用线程初始化）。触发：`future.create(fiber.resume, f)`。**用户决定：暂缓**（CovScript API 整体未考虑多线程）。移入 Backlog。
- **A5 [high]** 销毁挂起中的 fiber 不执行其 C 栈上的 RAII：值栈槽泄漏、终结器丢失。`win32/common.cpp:223-227`（DeleteFiber）、`unix/common.cpp:291-295`（munmap）。触发：`var co=fiber.create(f); co.resume(); co=null;`。**用户倾向：禁止/断言销毁未结束 fiber**（实现方案：状态机检查 + 调试模式断言）。**【实现修正】**：完全解冻并展开外来 C 栈不可行（协作式取消可被脚本 try/catch 吞掉），RAII 跳过在"废弃挂起协程"场景下无解；保留 debug 断言 + release 警告，但**修正 win32 原实现的 `return`——它连 DeleteFiber 都跳过，导致每个被丢弃的挂起纤维漏 1MB 栈**（unix 版本就正常释放）；现 release 下警告 + 正常释放栈，debug 下仍断言禁止。**Phase 2**
- **A6 [high]** `future.create`/`await` 的 std::async 线程与主脚本并发操作全局 any 代理池（非线程安全分配器/引用计数）。`type_ext.cpp:1373,1407`、`include/covscript/core/variable.hpp:822-828,838-854`、`components.hpp:867-924`。**【二次核查】** 用户疑问"难道现在不是仅限纯 CNI 吗"——实测**不是**：A1 已验证 lambda 可进 async。且 `allocator_type`（components.hpp:867-924）确认为**完全无锁**（`mOffset` 普通计数、`free`/`allocate` 直接操作池），proxy refcount 非原子（variable.hpp:816-854）。**【方案已定】从 CNI 层适配：池改 `thread_local`**（variable.hpp:824-828 一处 `static thread_local allocator_t allocator`）。依据：async 工作线程上**新分配只发生在"具体返回类型"CNI 的返回路径**（`return_to_cs`，cni.hpp:238-247；`var`/`any` 返回仅 refcount++ 不分配），参数经 `detach_args` 后由 worker 独占——每线程独立自由表即可消除跨线程池竞争；cross-thread free（worker 造的 proxy 由主线程归还）对定长 proxy 内存安全。**refcount 保持非原子**：detach 后 args 由 worker 独占、返回值 worker 创建后顺序移交主线程，无并发计数。**TLS 代价实测**（Win64/MinGW -O2，alloc+free 微基准 2 亿次）：global 池 2.22-2.32 ns/op，thread_local 池 1.31-1.35 ns/op——TLS 读取 <1ns（TEB 段相对加载，常驻 L1），同步热路径**零可测退化**（先前"2-3ns"估计为高估）。配套约束（文档化）：async 仅限纯 CNI（配合 A1）。**Phase 2**
- **A7 [medium]** `process_context::fork()` 监听器按值捕获裸指针 `curr`，父先析构则子 UAF；且不复制调度参数。`sources/covscript.cpp:157-170`。修复：共享所有权或文档化生命周期。

### B. 生命周期 / GC 设计（Phase 4）

- **B1 [high]** `function_ptr` 指向语句成员 `mFunc`（裸指针），语句由全局 GC 池释放 → 嵌入式 API（eval/function_invoker）、调试器函数断点、fiber_function 持有悬垂。`sources/instance/statement.cpp:828-843`、`sources/covscript.cpp:620-646`、`include/covscript/covscript.hpp:109-158`、`sources/debugger.cpp:180-260,660-717`、`type_ext.cpp:1538-1565`。**用户方向：采用全局 GC，不用 shared_ptr**（效率考虑）。方案：语句/token/method 池改为**进程期内不朽**，仅在进程退出时统一回收；`function_ptr` 生命周期随之与进程同长。trade-off：调试器重复 run / 嵌入式反复 bootstrap 会累积已编译代码内存（若成为问题，后续可加按 context 归属的池回收作为演进）。**Phase 4**
- **B2 [high]** `collect_garbage()`（无参）全局删除所有语句；`raii_collector` 按 context 析构 → 多 context 场景 use-after-free。`covscript.cpp:620-646`、`covscript.hpp:109-126,148-151`。触发：同进程两 context 先后销毁。修复：GC 按 context 归属；`collect_garbage(context)` 不再触发全局池回收。
- **B3 [medium]** `garbage_collector::collect()` 用 `::operator delete` 不跑析构：token_value 持有的 var 引用、tree_node 链整体泄漏。`include/covscript/core/core.hpp:1280-1285`。修复：collect 改 `delete ptr`（跑析构）或显式析构。
- **B4 [medium]** domain 反射表键为不拥有所有权的 string_view，指向 AST token 字符串；无参 `collect_garbage()` 裸删 token 后键悬垂。`core.hpp:659`、`covscript.cpp:149-155`。修复：键改 std::string，或 collect 仅限进程退出前。

### C. 控制流 / 异常状态卫生（Phase 1 + Phase 3）

- **C1 [high]** `break`/`continue` 是全局布尔，函数调用边界不隔离 → 函数体内无循环的 `break` 穿透函数打断外层循环/块。`sources/instance/statement.cpp:47-63`（call_rr 只消费 return_fcall）、`65-110`（call_vv）、`112-159`（call_rl/call_el 完全不检查）、`293-308`（置位）、`315-332,374-443`（block/if 消费但不重置）、`458-467`（switch 不消费）。触发：`function f() break end` + 外层 loop。**用户方向：编译期检测，不做运行时 guard**。方案：code_gen 中维护循环嵌套深度计数器（while/until/loop/for/foreach 进入+1、`end` -1，**函数/lambda 体边界清零**），`method_break/method_continue::translate` 在深度为 0 时抛 compile_error。实测 `switch 1 / case 1 / break / end / end` 中 break 穿透 switch 打断外层循环（statement_switch 不消费 break）——**break-in-switch 语义需一并决策**：若 break 仅限循环，则编译期检测直接拒绝；若需支持"break 退出 switch"，则 statement_switch 须消费 break_block 且编译期把 switch 视为 break 目标。**Phase 1**
- **C2 [medium]** 异常展开不复位标志；try 的 catch 体在脏标志下执行。`statement.cpp:878-914`。修复：与 C1 合并，函数边界隔离即可覆盖。**Phase 1**
- **C3 [medium]** REPL 块错误后 domain/set 栈永久错位（reset_status 不回滚 add_domain/add_set）。`include/covscript/impl/impl.hpp:145-155`、`sources/instance/instance.cpp:397-403,412-431`。触发：REPL 中输入非法块语句。修复：reset_status 按 methods 深度配对弹栈。**Phase 3**

### D. 优化器正确性（Phase 1 + Phase 3）

## 4. 总体健康度评估

核心价值模型（引用计数 proxy + protect 级别 + scope_guard/fcall_guard RAII、domain_ref 身份比较免疫悬垂）设计健全，正常单线程路径自洽。主要风险集中在三处系统性弱点：

1. **async/fiber 的"native 判据"过粗 + 进程全局状态（值栈/GC/any 池）无线程隔离**（A 簇）——新特性引入，可由脚本直接触发。
2. **function 生命周期依赖 GC 池裸删 + 全局 GC 作用域错配**（B 簇）——嵌入式/调试器 UAF。
3. **控制流标志是无作用域全局布尔 + 优化器"折叠即执行"**（C/D 簇）——逻辑缺陷与常量不可变保证被打破。

其余为畸形输入崩溃（修复便宜）与边界健壮性问题。

- **A1/A2 实证**：`future.create([](x)->x*2, 21)` 返回 42（lambda 被 async 接受并执行）；`future.create(fib, 15)`（命名函数）被拒；`fiber.create([]()->...)` 走 native 分支正常运行。**lambda 编译为 `callable(cs::function)`，非 function_ptr**（compiler.cpp:826 vs statement.cpp:833），用户疑问解除。

- **A4**：按用户决定暂缓。**A5**：采用禁止/断言销毁未结束 fiber。
- **A6 方案定稿**：any 池改 `thread_local`（variable.hpp:824-828），refcount 保持非原子，async 限纯 CNI（配合 A1）。**TLS 实测**：Win64/MinGW -O2，alloc+free 微基准 2 亿次——global 2.22-2.32 ns/op、thread_local 1.31-1.35 ns/op（TLS 读取 <1ns，同步热路径零可测退化）。worker 线程上仅"具体返回类型 CNI"的返回路径新分配（`return_to_cs`，cni.hpp:238-247）；`var` 返回仅 refcount++。cross-thread free 对定长 proxy 内存安全。
